# UI 教训记录

每次界面上犯的错、被用户纠正的地方，都记在这里：错在哪、根本原因、以后怎么防。能写成程序的，同时写进 `scripts/ui-check.py`（C 开头）或 `scripts/ui-shot-check.py`（S 开头），让它自动拦住，不靠记性。

**怎么用**
- 改界面前读一遍；`CLAUDE.md` 规则 6、7 是流程。
- 检查失败时，输出里的 `lesson Lx` 指向下面对应的一条。
- 用户每纠正一次，就加一条 `L`；能程序化的，同时加一个检查，并在仓库副本里**故意造一次这个错误，确认检查能拦住**再提交。
- 规则的例外（比如悬停时对比度下限 4.0）只写进 `design/tokens.json`，并注明是谁、哪天同意的。

**自动检查在哪里跑**
- 我每次编辑文件后：Claude Code 钩子（`.claude/settings.json`）运行 `ui-check.py --hook`，失败的内容直接反馈给我。
- 每次提交前：`.githooks/pre-commit` 运行 `ui-check.py`，失败就拒绝提交。新克隆的仓库要先执行一次 `git config core.hooksPath .githooks`。
- 界面改动装进 Herdr 后：运行 `python scripts/ui-shot-check.py`（会自己截图）。

## L1 颜色凭感觉调（2026-11-25）
- **错在哪**：浅色主题先是我自己把 paper 的颜色调深一点，用户说"颜色奇怪、对比度差、刺眼"；又换成 Primer，最后才定成 shadcn + Apple。做了三遍。
- **根本原因**：没先定设计来源就动手，颜色是猜的。
- **以后**：每个颜色都要能说出取自哪个公开来源的哪个令牌，从官方源码或页面数据里取，登记进 `config/themes/sources.json`。
- **自动检查**：C1（主题色值必须和登记的来源换算一致）、C4（mod 代码里不能新增写死的颜色）。

## L2 数值凭记忆写，规格边做边补（2026-11-25）
- **错在哪**：当前项指示条说成 2px，Primer 实际是 4px；右键菜单先照 Herdr 原生做，方向定下后又按 shadcn 重做。
- **根本原因**：没先查官方规格；没在动手前把这个界面所有部件的规格一次定完。
- **以后**：先从官方源码取数值，整套规格写进 `docs/REQUIREMENTS.md` 和 `design/tokens.json`，用预览截图确认后再写代码（`CLAUDE.md` 规则 6）。
- **自动检查**：C9（共用菜单和对话框的常量必须等于 `design/tokens.json`）、C7（弹出层高度必须由 `menuHeight()` / `confirmHeight()` 算出，不能手算）。

## L3 对比度用错了底色（2026-11-25）
- **错在哪**：space 淡底色的浓度前后算了四次（12% → 8% → 5% → 8% / 4%）。第一次假设侧边栏底色是面板色，实际是 `chrome`；每换一次主题又要重算；悬停、选中叠加之后的情况也漏算过。
- **根本原因**：手算，而且没有用真实的叠加底色。
- **以后**：对比度永远在真实底色上算，并包括叠上 `hover` / `selected` 之后的颜色，深浅两套都算。
- **自动检查**：C2（所有文字色在所有底色上：普通状态 ≥ 4.5，悬停 / 选中 ≥ 4.0；当前项指示条 ≥ 3.0；space 淡底色行上的次要文字也算在内）。

## L4 规则写在文档里，但没人核对（2026-11-25）
- **错在哪**：共用件 `settings.js` 的 4 份副本里有 1 份悄悄变了样；菜单项大小写不统一（`Discard Changes` 和 `Copy path` 混用）；Windows 上叫 `Show in folder`，没按约定叫 `Reveal in File Explorer`。
- **根本原因**：规则只靠人记，没有程序核对。
- **以后**：凡是写进 `CLAUDE.md` 或需求文档、而且机器能判断的规则，都要同时写成检查。
- **自动检查**：C5（共用件副本必须逐字节相同）、C6（界面字符串里不能有中文）、C7（菜单项用 sentence case，专有名词白名单在脚本里）、C8（引用的图标文件必须存在）。

## L5 对齐靠肉眼，被用户看出来（2026-11-25）
- **错在哪**：侧边栏底栏和状态栏的分隔线差了 12px，卡片四周的缝隙偏大，都是用户指出来的。
- **根本原因**：动手前没算版式里的横线、竖线位置；做完也没量截图。
- **以后**：版式数值进 `design/tokens.json`，布局之间的对齐关系写成检查；界面装进 Herdr 后跑截图核对。
- **自动检查**：C3（两条底栏一样高；品牌区高度 = 标签栏 + 缝隙；所有缝隙相同；卡片圆角相同），以及 S1～S3（截图里的底色、缝隙宽度、两条底线是否在同一行）。

## L6 操作路径只有去、没有回（2026-11-25，同一个错误犯了两次）
- **错在哪**：
  - 文件树能"上一级"，但上去之后回不到原来的文件夹，后来补了"进入选中的文件夹"。
  - 右键菜单的 `More agents…` 把整个菜单换成另一个菜单，再也回不去。
  - 排查时又发现第三处：用键盘把文件树从"跟随终端"变成"固定"之后，只能用鼠标点房子按钮恢复，键盘回不去。
- **根本原因**：我设计交互时只设计"前进"那一步，没有把用户的操作路径当成一张**可以往返的图**来设计。每个让用户"去到别处、进入另一个状态"的动作（换文件夹、进详情、打开预览、展开子菜单、切换模式、固定 / 跟随），都应该在设计时就配好"回来"的动作。
- **以后**：
  - **有去必有回**：每个"去"都要同时设计"回"，并且回来的方式覆盖去的方式：能用鼠标去，就能用鼠标回；能用键盘去，就能用键盘回。回来后停在合理的位置（比如上一级之后，选中刚离开的那个文件夹）。
  - 动手前先把所有"去 / 回"登记进 `design/flows.json`；预览时两个方向都要演示。
  - 回来的方式优先用常规做法：Esc、←、返回按钮、侧向展开的子菜单。
- **自动检查**：C11（`design/flows.json` 里每条路径"回"的方式必须覆盖"去"的方式，登记的步骤在代码里必须存在）、C10（菜单不许用"弹出另一个自己的菜单"做下一级）。
